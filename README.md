# biglybt-ProtonVPNPort
BiglyBT plugin to automatically set the current open port of Proton VPN.

### The problem being solved

In P2P mode, the Proton VPN client opens a random port to permit external Torrent clients to establish an inbound connection to the local client.  BiglyBT needs to be configured to listen on that port to take advantage of this open port.  This requires opening the options settings and manually reconfiguring the port each time a new VPN session is started.  An automated process is desired to get the current port number from the Proton VPN client and configure it in BiglyBT.

### The solution

This plugin for BiglyBT (formerly Azureus, Vuze) reads the latest port number listed in the log files generated by Proton VPN and, if necessary, reconfigures BiglyBT's incoming TCP and UDP ports to use that port.

It is primarily a Windows solution: it finds the Proton VPN client's log in its standard install location. On Linux and macOS it searches likely log locations, but those locations and log formats are unverified. You can always set the log path manually.

Since 0.1.1 the plugin also runs an experimental **NAT-PMP comparison trial**. It asks Proton's VPN gateway directly about the port the Proton app is forwarding and records whether the gateway confirms the port in the log. The log remains the source of truth, and NAT-PMP results never change BiglyBT's settings. The trial checks that the plugin can talk to Proton's gateway reliably. That's the groundwork for a future mode for setups without the Proton app (for example Linux with WireGuard), where the plugin would manage the port forward itself. See [docs/DESIGN.md](docs/DESIGN.md).

### How to install
(as a user - no code compilation required)

**Step 1 — Download the plugin file**

1. Open the latest release page: **[Download the latest release](https://github.com/Alex870/biglybt-ProtonVPNPort/releases/latest)**
   (You can also reach it from the repository's front page: on the right-hand side, under **Releases**, click the version marked **Latest**.)
2. Scroll down to the **Assets** section at the bottom of the release.
3. Click the file named **`ProtonVPN_x.x.x.jar`** (for example `ProtonVPN_0.1.1.jar`) to download it.

> **Which file?** Only the `.jar` file. Ignore the two **Source code** downloads (`.zip` and `.tar.gz`) that GitHub adds to every release automatically. Those contain the programming files, not the plugin.
>
> Your browser may warn that `.jar` files can be harmful. That warning is generic for this file type. Choose **Keep** to finish the download.

Older versions are listed on the [all releases](https://github.com/Alex870/biglybt-ProtonVPNPort/releases) page, each with its own **Assets** section.

**Step 2 — Install it in BiglyBT**

1. In BiglyBT, select: **Tools -> Plugins -> Install from file**
2. Locate the `.jar` file you downloaded (usually in your **Downloads** folder) and follow the wizard instructions.
3. Ensure the plugin is enabled: **Tools -> Options -> Plugins -> ProtonVpnPort**
4. Make sure "Enable" is checked.
5. Adjust parameters as desired and press the `Save` button.

**Updating:** download the newer `.jar` the same way and install it with **Install from file**. BiglyBT replaces the old version, and your settings are kept.

### Settings

| Setting | Default | Notes |
|---|---|---|
| Enable | on | |
| VPN port check interval | 60 s | Checked on a 15 s timer tick. The first check runs about 15 s after BiglyBT starts. Checks are cheap: the log is only copied and re-read when it has changed |
| Proton VPN log file | blank | Blank means auto-detect. Set a full path to override |
| Verbose logging | off | Errors, warnings and port changes are always logged. This adds per-check detail |
| Check now | — | Runs a check immediately |
| NAT-PMP comparison trial | on | Asks the gateway (default `10.2.0.1`) about the Proton app's port and compares the answer with the log. Never changes ports. Uses the same 60 s mapping lifetime as the app, which renews every 30 s. Turn it off if you suspect it interferes with the Proton app |
| Reset NAT-PMP trial statistics | — | Clears the counters shown in Status |

The **Status** group shows the log file in use, the last check result, the ports from the log and in BiglyBT, the last change, the last error, and a summary of the NAT-PMP trial. Messages appear in the plugin's log view (**View -> Plugins -> ProtonVpnPort**).

### NAT-PMP trial data

Each check appends a row to `natpmp-trial-v2.csv` in the plugin's folder inside BiglyBT's user directory (the full path is logged when the plugin loads). The file is capped at 1 MB, with one `.1` backup. Columns:

`timestamp_utc, log_kind, log_port, natpmp_kind, natpmp_tcp, natpmp_udp, outcome, tcp_udp_split, natpmp_rtt_ms, natpmp_internal_port, natpmp_lifetime_s, natpmp_epoch_s, log_file_mtime_utc`

Outcomes: `MATCH` (the gateway confirms the log's port), `MISMATCH`, `LOG_ONLY` (NAT-PMP failed). Checks where the log has no port are skipped. Please attach this file to an issue after a few weeks of use. It's part of deciding whether a NAT-PMP mode gets added (see [docs/DESIGN.md §6](docs/DESIGN.md)).

### Developer notes

Build with Maven (JDK 9 or newer; the plugin is compiled to Java 8 bytecode):

1. BiglyBT is not published to Maven Central, so compile against the `BiglyBT.jar` from a BiglyBT install. Either copy it to `Eclipse_Project/lib/BiglyBT.jar` (ignored by git), or pass its location:
   ```bash
   mvn -f Eclipse_Project/pom.xml package -Dbiglybt.jar="C:\Program Files\BiglyBT\BiglyBT.jar"
   ```
2. The plugin jar is written to `Eclipse_Project/target/ProtonVPN_<version>.jar`. The version comes from `pom.xml` and is copied into `plugin.properties` at build time.
3. `mvn test` runs the unit tests (log parsing, scheduling, file handling, NAT-PMP encoding and a local fake gateway, comparison tracking).

Eclipse can import the project as an existing Maven project.

Plugin jars are published as GitHub Releases, not committed to the repository. See [docs/RELEASING.md](docs/RELEASING.md) for how to make a release.

Prior art attempted to read the SQLite database of notifications generated by the Proton VPN client.  However, in testing it was found that the latest port data was stored in temporary database files whose data was not yet integrated into the main database file.  Thus there appeared to be no easy way to access the needed data.  No API appears to exist for the Proton VPN client.  Parsing the client's log file for the port number appeared to be one of the easiest ways to obtain the data.  And while brittle in the sense that a change of file path or formatting could potentially break the plugin, it would likely be trivial to fix.

The log is copied to a uniquely named temporary file before it is read, because the copy is fast and it isn't known how long Proton VPN holds the log file open.

See [docs/DESIGN.md](docs/DESIGN.md) for the architecture and roadmap.
